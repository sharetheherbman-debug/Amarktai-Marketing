# Marketing Frontend / Backend Separation Audit

> **Date:** 2026-05-21  
> **Status:** Post rebuild

---

## Principle

Users should never see raw backend field names, Python exception text, provider chain internals, or technical model identifiers in the main UI. These belong in an "Advanced details" accordion or in the Integrations/Diagnostics area only.

---

## Separation Status

### Main Content Cards (ContentStudio)

| Field | Backend field | User sees | Advanced only |
|---|---|---|---|
| Platform | `platform` | Human label (e.g. "Instagram") | No |
| Format | `format` | Human label (e.g. "Ad Campaign") | No |
| Status | `status` / `generationStatus` | Simplified label | No |
| Hook | `hooks[0]` | Yes | No |
| Caption / Body | `caption` / `videoScript` etc. | Yes | No |
| CTA | `cta` | Yes | No |
| Hashtags | `hashtags` | Yes | No |
| Warnings | `warnings` | Plain English | No |
| Rejection reason | `rejectionReason` | Plain English | No |
| Provider | `providerActual` | **Hidden** | ✅ Advanced only |
| Model | `modelActual` | **Hidden** | ✅ Advanced only |
| Source action | `sourceAction` | **Hidden** | ✅ Advanced only |
| Generated by | `generatedBy` | **Hidden** | ✅ Advanced only |
| Variation seed | `variationSeed` | **Hidden** | ✅ Advanced only |
| Grounding scores | `businessGroundingScore` etc. | **Hidden** | ✅ Advanced only |
| Fallback chain | `fallbackChain` | **Hidden** | ✅ Advanced only |
| Media job IDs | `mediaJobIds` | **Hidden** | ✅ Advanced only |
| Media asset IDs | `mediaAssetIds` | **Hidden** | ✅ Advanced only |

### Provider Readiness (ContentStudio header banner)

| What user sees | Backend source |
|---|---|
| "Text AI: Ready / Limited / Missing" | Derived from provider status |
| "Stock Assets: Ready / Missing" | Derived from Pixabay key |
| "Posting: Manual / Connected" | Derived from OAuth state |
| Link to Integrations | Static link |

No raw provider names, error messages, or stack traces shown in the banner.

### Integrations / Diagnostics (Settings)

This is the ONLY place where technical details are allowed:
- Provider key status
- Test endpoints
- Debug diagnostic JSON (providers/debug)
- Error classifications
- Fallback chain details
